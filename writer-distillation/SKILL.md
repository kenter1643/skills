# 作家蒸馏

## 核心原则

作家蒸馏不是仿写皮毛，而是提炼一套可运行的创作系统：
- **看见什么**：主题母题、伦理敏感度、人物观、现实观。
- **怎么组织**：叙事结构、场景推进、视角调度、时间处理。
- **怎么写句子**：句法节奏、意象系统、词汇质地、留白方式。
- **怎么修改**：删改习惯、质量标准、失败稿症状。
- **绝不做什么**：廉价煽情、风格过拟合、把技法误认为灵魂。

执行前读取：
- `references/writer-framework.md`：作家研究维度、提炼方法和质检门槛。
- `references/writer-skill-template.md`：作家专用 Skill 模板。

## 入口判断

使用此 skill 的典型场景：
- 用户点名某位作家，要蒸馏其写作方法或文风。
- 用户想提升小说、散文、诗歌、剧本、非虚构等文学写作能力。
- 用户提供自己的文本，希望借某位作家的方式诊断和改写。
- 用户要生成一个可长期调用的「某作家写作导师」Skill。

不适合的场景：
- 商业文案、社媒增长、技术写作优先使用对应内容/营销/技术写作 skill。
- 只需要一次性仿写短段落，不必生成完整 Skill；但仍要遵守版权与风格边界。

## 执行流程

### 1. 澄清目标

最多问 2 个问题，足够清楚就直接推进：
- 目标作家是谁？如果是流派/题材，先确认边界。
- 用途是写作导师、文本诊断、风格学习，还是角色视角？
- 文体重点是什么：小说、散文、诗、剧本、非虚构？
- 是否有本地语料：作品 PDF、访谈、写作笔记、草稿、手稿、评论集。

默认设置：全面蒸馏 + 写作导师 + 公开材料优先 + 不直接仿写在世作家的长篇新文本。

### 2. 建目录和研究文件

新建 `[writer-name]-writer/` 或 `[writer-name]-writing-mentor/`：

```text
references/research/
  01-primary-works.md
  02-craft-statements.md
  03-sentence-style.md
  04-narrative-architecture.md
  05-themes-ethics.md
  06-revision-practice.md
  07-reception-influence.md
  08-timeline-context.md
```

每个研究文件必须写入 skill 目录内部。调研结果不落盘等于没做。

### 3. 多维调研

按 `references/writer-framework.md` 的八维结构并行采集。优先级：
1. 完整作品与作者自述。
2. 访谈、讲座、书信、日记、写作课。
3. 草稿、手稿、修订记录。
4. 高质量文学批评、传记、同代人评价。
5. 社媒和碎片表达只作为辅助，不可替代作品本身。

必须区分：作者作品中的叙述者、作者公开自述、评论者观点、你的框架推演。

### 4. 提炼写作系统

输出前至少提炼：
- 3-7 个创作心智模型。
- 5-10 条写作启发式。
- 叙事结构和场景推进模式。
- 语言 DNA：句法、词汇、意象、声音、留白。
- 修订协议：怎么从坏稿改到可用稿。
- 伦理边界：哪些模仿会变成廉价复刻或版权风险。

### 5. 构建 Skill

用 `references/writer-skill-template.md` 生成最终 `SKILL.md`。默认定位为「写作导师」而不是「冒充本人」：
- 可以用第一人称讲方法，但不要声称自己就是作家本人。
- 可以分析用户文本、给改稿路径、提供风格练习。
- 对在世作家，不输出大段可替代市场需求的仿写文本；优先给方法、诊断和短小示例。

### 6. 验证

至少做三类测试：
- **作品一致性**：用 2-3 个作者已知创作选择验证模型是否解释得通。
- **文本诊断**：给一段普通文本，检查是否能提出该作家式的具体改稿建议。
- **风格边界**：确认输出不是通用 AI 文青腔，也不是逐字仿冒。

通过标准见 `references/writer-framework.md`。

## 常见错误

| 错误 | 修正 |
|------|------|
| 只抓口头禅和句式 | 回到作品，提取结构、观察方式和修订标准 |
| 把叙述者观点当作者观点 | 标注「作品声音」与「作者自述」的区别 |
| 用二手评论代替一手阅读 | 二手评论只能解释，不可作为主证据 |
| 长篇仿写在世作家 | 改为方法拆解、文本诊断、短示例和练习 |
| 只讲风格不讲产出流程 | 加入选材、起稿、场景、删改、验收协议 |

## 交付物

最终交付一个可运行的作家写作 Skill，包含：
- 使用场景和触发词。
- 写作导师协议。
- 创作心智模型。
- 叙事与语言工具箱。
- 文本诊断和修订流程。
- 风格边界和版权边界。
